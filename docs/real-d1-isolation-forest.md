Выполнено 13.10.2026 на Go 1.27.2, Windows/amd64. Ветка
`feat/isolation-forest` основана на `main` / `addeb74599b3f5b3c29580a7dca5ee683daa91bd`.

## Алгоритм и интеграция

Один общий лес использует 18 исходных F18 для всех 288 узлов. Нормализация
вызывает прежний `StatisticalProfile.Normalize`; median/MAD/scale копируются
из существующего D1-профиля. Статистическое ядро, CPU/GPU/PSU-регрессии,
Reader/WindowReader и PostgreSQL не изменены.

Сверка с актуальной компонентной РПЗ
`НИР7_Буторов_РПЗ_07_10_2026_компонентная_модель.docx`:
§2.3 требует общую median/MAD-нормализацию всех пригодных F18 на D1;
§3.2 — один IF на том же представлении без числовых идентификаторов и времени;
§3.3 — непрерывную оценку с направлением «выше = нетипичнее». Эти положения
сохранены. Бинаризация и F1 из дальнейшей части §3.3 отложены до мини-ТЗ №4.
Старое описание трёх календарных дней в РПЗ заменено явно согласованными
восьмичасовыми окнами одного дня 18.01.2022; сама РПЗ не редактировалась.

`analysis.Data` передаёт только полные конечные состояния D1, а ядро повторно
проверяет каждый timestamp. Для каждого из 100 деревьев Algorithm R выбирает
256 наблюдений без возвращения из всего потока D1. Выборки разных деревьев
независимы и могут пересекаться. Память выборок — 3 686 400 байт для векторов
(100×256×18×8), плюс RNG, деревья и буферы Reader. Все состояния F18 в RAM
не собираются. Обучение выполняет один проход; описание score — второй.

Начальный seed 42 детерминированно задаёт отдельные `math/rand` RNG деревьев.
Порядок данных сохраняется timestamp → group → hostname. Выбор признака
равномерный среди неконстантных координат текущей ветви, разрез — равномерный
между минимумом и максимумом с защитой округления на границах. Константный
признак пропускается; константные векторы образуют лист. При максимальной
глубине 8 построение прекращается. Глубина корня равна нулю.

Формулы соответствуют [Liu, Ting, Zhou, Isolation Forest (ICDM 2008)](https://cs.nju.edu.cn/zhouzh/zhouzh.files/publication/icdm08b.pdf):

```text
c(0)=c(1)=0; c(2)=1
c(n)=2 H(n−1)−2(n−1)/n
path(x)=depth(leaf)+c(leaf.size)
score(x)=2^(−mean_tree(path(x))/c(effective_sample_size))
```

Гармонические числа вычисляются точной конечной суммой, без приближения
`log(n−1)+gamma`. Поэтому численное совпадение с библиотеками, применяющими
это приближение, не предполагается. Поправки кешируются при fit/validation;
Score не меняет модель. Если данных меньше `sample-size`, используется их
фактическое количество; меньше двух состояний — ошибка. Константный лес
или глубина 0 дают score 0,5. Настройки конфигурируемы; инженерные пределы:
1–10 000 деревьев, sample 2–65 536, глубина 0–64, trees×sample ≤ 10 000 000.

JSON-envelope содержит версию `isolation-forest-v1`, конфигурацию, фактический
размер выборки, число обучающих состояний, параметры нормализации, деревья,
порядок F18, окно D1 и идентификаторы обоих источников. Загрузчик проверяет
версию, конечность коэффициентов, размеры и глубину дерева, сохранение размера
между потомками, SHA-256 и топологию Parquet, порядок F18 и SHA-256 исходного
Stage A JSON. Копия Stage A по другому пути допустима при тех же байтах.
Изменение его содержимого, включая форматирование, меняет идентификатор.
Перед параллельным Score модель должна быть валидирована; Validate готовит
кеш и не должна вызываться одновременно с inference на той же модели.

## Проверки и воспроизведение

Выполнены `go test ./...`, `go build ./...`, `go vet ./...`: exit code 0.
Unit-тесты проверяют c(n), ручные деревья и поправку листа, маршрутизацию
равенства вправо, константы, effective sample, дубликаты, порядок score
синтетического выброса, одинаковый seed, JSON round trip, неизменность
нормализатора и inference, один проход, границы D1, NaN/Inf/overflow,
отмену context, повреждения деревьев и несовпадения идентификаторов envelope.
Реальные IF reload и повторное обучение выполнены отдельно, сверх обычных
unit-тестов. DB-интеграция без `TEST_DATABASE_URL` и остальные opt-in реальные
проверки без их переменных остаются SKIP; PostgreSQL для IF не требуется.

```powershell
go run ./cmd/isolation --statistical-profile results/statistical-20220118-8h-v1.json --trees 100 --sample-size 256 --max-depth 8 --seed 42 --output results/isolation-fresh.json
go run ./cmd/isolation --statistical-profile results/statistical-20220118-8h-v1.json --profile results/isolation-fresh.json --output results/isolation-fresh-reloaded.json
$env:NIR_REAL_PARQUET=(Resolve-Path data/prepared/summit-D1-pilot/D1.parquet).Path
$env:NIR_REAL_PROFILE=(Resolve-Path results/statistical-20220118-8h-v1.json).Path
$env:NIR_REAL_ISOLATION_PROFILE=(Resolve-Path results/isolation-fresh.json).Path
go test -v ./internal/experiment -run TestRealIsolationProfileReloadD1 -count=1
python tools/dataset/verify_isolation.py --profile results/isolation-fresh.json --input data/prepared/summit-D1-pilot/D1.parquet --statistical-profile results/statistical-20220118-8h-v1.json
```

Последняя команда требует Python с NumPy и PyArrow. На этой машине использованы
bundled Python и существующий `.venv/Lib/site-packages` через `PYTHONPATH`;
пакеты и глобальная среда не изменялись. Имена outputs должны быть новыми.

Ограничения сохранены: UTC первичного источника остаётся прежним неподтверждённым
допущением manifest; группы a01–a16 — прежняя выбранная топология. Score
характеризует редкость состояния относительно D1, не подтверждает аппаратную
неисправность и сам по себе не является детектором групповых аномалий.
Порог, F1, бинарная классификация и итоговое D3-испытание не входят в мини-ТЗ №3.
