# Групповое обнаружение Summit: математическая спецификация

Версия предложения 1, 17.10.2026. **Статус: для согласования с П. А. Паниловым.**
Реализован только локальный B1. Все численные соглашения группового уровня ниже
являются предлагаемым заранее фиксируемым контрактом, а не результатом поиска
оптимума на D2/D3. В этом этапе групповой код и временная state machine не создаются.

## 1. Область, время и топологическая модель

Пусть H_g — фиксированные 18 hostname группы g из a01–a16, G — выбранные группы,
Δ=10 s. x_h(t)∈R¹⁸ — F18 на сетке суток 18.01.2022. Обучение только D1
`[00:00,08:00)`, исследование D2 `[08:00,16:00)`, D3 `[16:00,24:00)`.
UTC — сохраняемое неподтверждённое допущение источника. Не смешивать это разбиение
с историческими тремя календарными днями Builder.

Топология — разбиение множества узлов по hostname: гиперрёбра H_g, подтверждённые
inventory. Физические рёбра питания/охлаждения/InfiniBand между выбранными узлами
не установлены. Название группы не доказывает принадлежность общей стойке или
контуру. Известная архитектура Summit не даёт такого отображения hostname сама
по себе. Будущие физические связи должны иметь отдельные provenance и версии.

Идентификатор профиля включает SHA prepared, модель B1, список и порядок хостов,
F18 order, окна, feature schema, все параметры, доступность, numerical rank и
timezone assumption. Изменение состава группы требует нового профиля.

## 2. Два уровня и доступность

Локально используется один замороженный IF, общая D1-нормализация,
`theta_h=Q_.99{score_IF(x_h(t)):t∈D1}`, `L_h(t)=[score>theta_h]`.
Точный квантиль — существующий `analysis.EmpiricalQuantile`: порядковая статистика
с индексом `ceil(q*n)-1` для n>0 (с допустимыми границами q), строгое сравнение.
Неполное состояние/неизвестный хост/порог не дают L=0, а дают unknown.
Контракт и SHA описаны в [local-b1.md](local-b1.md).

На групповом уровне три параллельных сигнала R, Y, B ∈{1,0,?}.
`?` означает неизвестность, `not_applicable` хранится отдельно у конкретного
паспортного параметра. Оно не превращается в отрицательный голос Y.

Основной статистический контракт требует **всех 18 полных конечных F18** на t.
Иначе R(t)=B(t)=?. Это осознанно консервативное правило c_min=1: среднее/разброс
по изменяющемуся составу нельзя сравнивать с профилем фиксированного состава.
Не интерполировать и не заполнять нулями. Сохранять n_valid, n_expected=18,
маски отсутствующих хостов/признаков. IF-support может быть доступен частично.
Снижение c_min или профили по подмножествам — отдельное согласованное расширение.
Полнота телеметрии не означает наличия аппаратного паспортного предела.

## 3. Компактное описание состояния

Из F18 строятся пять величин узла u_h(t), в фиксированном порядке:

| k | Величина | Формула | Единица |
|---|---|---|---|
| 1 | GPU power | сумма шести GPU power | W |
| 2 | CPU power | сумма двух CPU power | W |
| 3 | PSU input | сумма двух PSU AC input | W |
| 4 | GPU temperature | среднее шести GPU core temperature | °C |
| 5 | CPU temperature | среднее двух CPU core-temp means | °C |

Это измерительные каналы разных границ; PSU input не равно сумме CPU+GPU.
Внутриузловые температурные максимумы и отдельные GPU этим компактным вектором
не сохраняются: исходный F18 и локальный IF остаются отдельными свидетельствами.

Основной групповой вектор v_g(t)∈R¹⁰:

`mu_gk = (1/18) sum_{h∈H_g} u_hk`,
`sigma_gk = sqrt((1/18) sum_h (u_hk-mu_gk)^2)`,
`v_g=(mu_g1,…,mu_g5,sigma_g1,…,sigma_g5)`.

Это population spread текущей фиксированной группы, а не оценка дисперсии
обучающей выборки с ddof=1. Средние отражают общий режим/нагрев/потребление;
разброс — неоднородность, включая отклонения противоположных знаков.
Отдельные totals=18*mu избыточны. Если r узлов изменяются на a в одном канале,
mean сдвигается на r*a/18; поэтому согласованность усиливает сигнал, но
обнаружение любого изменения двух узлов не гарантируется. Для одинакового
исходного уровня и r сдвинутых узлов spread=|a|sqrt((r/18)(1-r/18)).

Альтернатива — только пять mean-компонент (d=5), если D1 показывает
неидентифицируемость spread-координат. Выбор требует явного решения и новой
версии профиля до итоговой проверки, не автоматического fallback.
Локальную долю IF и coverage не включать в Mahalanobis: иначе подтверждение
тем же IF становится частью группового эталона, а пропуски — псевдоаномалиями.

Простая групповая медиана скрывает изменения менее половины хостов. Например,
16 одинаковых значений и два высоких дают прежнюю медиану и нулевой spatial MAD.
Поэтому для R предлагается temporal median/MAD отдельных узлов и объединение
по двум хостам, а не только spatial median группы.

## 4. Критерий R: согласованное маргинальное отклонение

Для каждой группы, хоста h∈H_g и k=1…5 по пригодным **полным групповым** D1-ticks:

`m_hk=median_D1 u_hk`,
`s_hk=max(1.4826*median_D1 |u_hk-m_hk|, epsilon_k)`,
`z_hk(t)=(u_hk(t)-m_hk)/s_hk`.

Предлагаем epsilon_k=1e-4 в единице соответствующего канала (W или °C),
как явно версионируемое численное соглашение. Это не sensor resolution и
не паспортный предел. Доли floored scales обязательно показывать; постоянные
координаты могут реагировать на любое небольшое изменение. Не исправлять это
скрытым увеличением epsilon по D2. При отсутствии D1 profile R=?.

Пусть secondlargest берёт второй элемент по убыванию среди 18 различных хостов.

`r_g(t)=max_{k=1…5, a∈{-1,+1}} secondlargest_h max(a*z_hk(t),0)`.

`tau_Rg=Q_.99{r_g(t):t∈D1}`, `R_g(t)=[r_g(t)>tau_Rg]`.
Это один calibrated maximum statistic на группу, а не десять независимых
порогов без поправки. Нужны не менее двух хостов одного канала и направления.
Свидетели: k,a, все хосты с a*z>tau_Rg, individual z. При равенстве maxima
выбирать меньший k, затем a=-1, для воспроизводимого краткого объяснения.
Два экстремума на разных каналах или противоположных знаков R могут не дать:
это намеренно различается с B. Квантиль на обучающей выборке не гарантирует 1%
ложных событий вне D1; ties и строгий знак дополнительно меняют долю.

## 5. Критерий B: совместное групповое отклонение

Это **новая групповая** модель v_g, не существующий узловой D² по F18.
Для каждой группы отдельно, по полным D1-ticks T_g (N_g=|T_g|):

`a_gj=median v_gj`, `b_gj=max(1.4826*MAD(v_gj),epsilon_j)`;
для mean и spread использовать epsilon соответствующих W/°C.
`w_gj=(v_gj-a_gj)/b_gj`, `bar_w=(1/N_g)sum_t w_g(t)`,
`C_g=(1/(N_g-1))sum_t (w_g(t)-bar_w)(w_g(t)-bar_w)^T`.

Центр и ковариация вычисляются существующей корректной схемой Welford,
ddof=1; d=10, N_g≥d+1 — минимальная алгебраическая пригодность, не доказательство
достаточного объёма зависимого временного ряда. Хранить N_g и D1 coverage.
SVD использует относительный cutoff=1e-12, как numerical convention проекта.
Сохранять спектр, эффективный ранг, condition number, reconstruction diagnostics.

`D²_g(t)=(w_g(t)-bar_w)^T C_g^+ (w_g(t)-bar_w)`,
`tau_Bg=Q_.99{D²_g(t):t∈T_g}`, `B_g(t)=[D²_g(t)>tau_Bg]`.

Предлагаем разрешать бинарный B только при конечной валидной PSD covariance
и эффективном rank=d. Если rank<d, B=? с `rank_deficient`; не выдавать нулевую
проекцию на nullspace за норму. Очень большой condition number публикуется
и требует диагностики D1 до принятия профиля; универсальный новый порог κ
без анализа не назначается. Ошибка/overflow даёт unknown с диагностикой.
Ridge или удаление координат не включаются автоматически. Существующий узловой
алгоритм, включая pseudo-inverse, не изменяется этой новой политикой.
Ни χ²-порог, ни гауссовость, ни независимость ticks не предполагаются.
Порог оценивается на тех же D1, что центр/ковариация: это in-sample calibration
с возможным оптимизмом; он фиксируется как ограничение будущего протокола.

R ищет минимум два сильных одномерных согласованных отклонения. B может
выявить умеренные совместные изменения и необычное сочетание mean/spread
без экстремума отдельного хоста. Но оба зависят от той же F18/D1 и могут быть
почти эквивалентны. Если D²=phi(r) для монотонной phi, пересечение R&B сводится
к более строгому одному порогу: независимого подтверждения нет.
Нельзя перемножать false-positive rates. Проверять D2 contingency R/B,
Jaccard, phi (при ненулевых знаменателях), conditional increments, вклад
каждого метода и события, возникающие только у одного, с временными блоками.
Если дополнительного смысла нет, пересмотреть концепцию с руководителем,
а не объявлять два коррелированных голоса независимыми.

## 6. Критерий Y: применимый аппаратный предел

См. [паспортный эталон](summit-hardware-reference.md). Для device d хоста h
и параметра j допустим тест только с подтверждёнными SKU, F18 mapping,
единицей, границей измерения, временной агрегацией и hard/sensor bound [l,u].
`y_hdj=[value<l OR value>u]` для имеющихся подтверждённых границ;
равенство пределу не является превышением. Направления без границы не тестируются.
TDP, nominal и неподтверждённый GPU board maximum не становятся такими u.
При несовместимом датчике — not_applicable; при недостатке сведений/измерения — ?.

На хосте: y_h=1 при любом проверенном положительном тесте; y_h=0, если
непустой заранее определённый набор применимых обязательных тестов весь доступен
и отрицателен; иначе ?. Объём проверенных параметров хранится, даже если y_h=1.
Пустой набор не даёт отрицательный голос.

На группе: p=число хостов с y_h=1, u=число с y_h=?;
`Y=1 if p≥2; Y=0 if p+u<2; Y=? otherwise`.
Это минимум два различных хоста; два GPU одного хоста не дают два голоса.
Если только один применимый хост и остальные не имеют проверенных границ,
невозможность второго подтверждения остаётся неизвестностью, а не нормой.
Сохранять device-level evidence и applicability coverage.
По текущим сведениям основной ожидаемый статус Y — unknown. Частоту его
срабатываний без соответствующих sensor bounds оценить нельзя.

## 7. Трёхзначное голосование и политика отсутствующего Y

Для трёх сигналов определим p=#1, u=#?.
`vote2=1 if p≥2; 0 if p+u<2; ? otherwise`.
На полностью доступных данных это `(R∧Y)∨(R∧B)∨(Y∧B)`.
Примеры: (1,1,?)→1; (1,0,?)→?; (0,0,?)→0.

Две допустимые **альтернативы**, требующие фиксации до запуска:

1. `degraded_rb`: при Y=? разрешить R=B=1 как групповой кандидат с
   `criteria_incomplete=true`, `mode=degraded_rb`; это не полная проверка трёх
   физических/статистических оснований. Иначе использовать vote2 и сохранять ?.
   Для двух 0 отрицательный R/B результат не доказывает исправность оборудования.
2. **Основное предложение `require_y_applicability`:** при Y=? общий статус
   `insufficient_criteria`, R/B и их пересечение только preliminary signals.
   Это более строгая политика принятия результата, чем чистая логика vote2.
   При известном Y использовать vote2. Наличие Y=0 не требует его срабатывания:
   два R/B всё ещё могут дать кандидата.

Первый вариант позволяет исследовать статистические события сейчас, но R/B
зависимы. Второй честно останавливает полноценное заключение, однако может
не дать ни одного окончательного события при нынешней неопределённости Y.
Выбор варианта не выполняется автоматически. До согласования сохраняются
три критерия и предварительные результаты, без подстановки false вместо unknown.

## 8. Временное объединение

Задать δ∈{0,10,30,60} s. Основной минимальный вариант δ=0; все четыре — заранее
объявленный анализ чувствительности, не четыре попытки выбрать лучший по D3.
Используется время наблюдения t на сетке, не время выполнения операции.

Для каждого метода m зададим causal occurrence-state A_m(t):

- A=1, если существует положительный свидетель s∈[t−δ,t], и все значения
  метода на ticks от s до t известны;
- A=0, если весь участок `[max(split_start,t−δ),t]` известен и положительных нет;
- A=?, иначе.

Unknown прерывает актуальность более раннего свидетельства, но новое
положительное после разрыва сразу может дать A=1. Known negative не отменяет
положительное в пределах TTL: объединяются **факты срабатывания**, а не только
текущие состояния. TTL применяется после текущей проверки пригодности модели;
неприменимость Y не лечится старым срабатыванием. На границе D1/D2/D3 память
сбрасывается: нет переноса D1-свидетельств в D2.

На каждом t применить vote2 к A_R,A_Y,A_B, затем выбранную политику Y.
При двух A=1 найти пару разных методов с witness times s_i,s_j и
`max(s_i,s_j)-min(s_i,s_j)≤δ`; это следует из общего trailing window.
Для воспроизводимости выбирать пару с наименьшим span, затем наиболее поздним
max(s), затем лексикографический порядок B,R,Y. Внутри метода выбирать самое
позднее пригодное положительное s. Хранить также все активные методы.

Срабатывание одного метода может предшествовать другому на δ. Первый момент
подтверждения — первый tick с двумя актуальными свидетелями. При δ=0 требуется
одновременность. Пример: R в 08:00:00, B в 08:00:10, все промежутки известны;
δ=0 не даёт пары, δ≥10 даёт её в 08:00:10. Если R=? в 08:00:10, старое R
не действует; если оба метода 0 после двух срабатываний, TTL ещё может удерживать
кандидата. Это продление явно входит в event duration.

Сегментация: одно событие — максимальная последовательность соседних ticks
с подтверждённым кандидатом. Первый tick открывает событие; следующие обновляют
тот же ID. Известный false закрывает на последнем positive tick; unknown
закрывает с `right_censored_by_missing=true`, а последующие positives начинают
новое событие. При конце файла/окна — `right_censored_by_window=true`.
Gap merging G=0: не склеивать интервалы поверх разрывов; TTL уже реализует δ.
Продолжительный положительный участок даёт одно событие, не новую тревогу
на каждом tick. ID детерминирован из run-config SHA, group и first-confirmed tick.
`duration_grid=(last_positive-first_confirmed)+Δ`; показывать отдельно span
реальных raw positives и TTL extension. Изменение δ меняет и частоту, и длины.

Различать времена:

- `first_evidence_time=min(s_i,s_j)` — начало наблюдаемого свидетельства пары;
  не установленное истинное начало неисправности;
- `detected_event_time` — первый t, когда причинное правило подтвердилось;
- `closed_event_time` — tick false/unknown либо граница окна;
- `emitted_at` — wall-clock подтверждения; транспорт, watermark wait и compute
  latency измеряются отдельно. Нельзя вычитать timestamp 2022 из wall-clock 2026.

Алгоритмическая задержка пары `detected_event_time-first_evidence_time` при
первом подтверждении ≤δ; задержка от реального физического onset неизвестна.
Данные 10 s не разрешают субсекундную локализацию. Offline backdating к
first_evidence не означает, что online-система могла знать событие раньше.

Будущая асинхронная система: обрабатывать ticks в event-time order после
watermark `min(required_source_watermarks)`, с отдельно согласованным bounded
lateness L. На барьере все необходимые host/method результаты известны или
явно помечены timeout/unknown. Сведения будущих ticks не используются.
Результат сверх L помещать в late-data stream; ретроспективная коррекция имеет
отдельную версию, не молча меняет отправленное событие. Незавершённый метод
не считается false. Watermark/state machine здесь только контракт.

## 9. Локальная поддержка IF и сравнение групп

`n_g(t)=# {h∈H_g: LocalResult.is_available}`, `a_g(t)=# {available and anomaly}`.
`S_g(t)=a_g/n_g` при n_g>0, иначе ?; всегда публиковать n_g/18 и причины
недоступности. Один доступный аномальный узел даёт S=1 при coverage=1/18,
а не эквивалент 18 аномальным узлам. Event summaries: min/mean/max S по
доступным ticks, counts и coverage, без замены неизвестных нулями.

Вариант A (IF gate) требует дополнительно `S≥s0` и минимального coverage,
которые нельзя выбирать без отдельной D1-калибровки. Он способен пропустить
коллективное изменение: все индивидуальные score ниже theta, но совместный
group vector необычен. **Основной вариант B:** IF — объясняющая характеристика,
не обязательный gate и не четвёртый голос. Поэтому s0 сейчас не назначается.

Вне группы: `S_outside_g=(sum_{j≠g} a_j)/(sum_{j≠g} n_j)`,
`E_g=S_g-S_outside_g`, если оба знаменателя положительны; иначе ?.
Это взвешивание по реально доступным хостам, не среднее долей групп.
Фиксировать состав outside и coverage, особенно при сравнении 4/8/16 групп.
E — характеристика локализации, не gate. Положительное E помогает локализовать,
но E≈0 не опровергает синхронное общекластерное событие.
Публиковать временную карту кандидатов всех групп и raw scores: одна группа,
несколько синхронных групп, широкое изменение режима. Без job/hardware logs
эти классы описывают пространственный охват, не причину и не доказанный отказ.

## 10. Контракт события и псевдокод

Event содержит: ID, group/host inventory и config/model/profile SHA; mode
(full/degraded/preliminary), raw/temporal R,Y,B с причинами unknown; scores,
thresholds, witness devices/hosts/directions/times; first evidence, logical
detection/end, emission, censoring, raw/TTL durations; coverage/missing masks,
IF counts/S summaries, outside coverage/E, список затронутых групп.
Необязательная внешняя fault-label хранится с независимым provenance;
псевдометка узлового D² не называется fault-label.

```text
OFFLINE FIT (D1 only):
  freeze source/model/config hashes and host partitions
  for each group: collect complete fixed-composition D1 ticks
    fit host-channel temporal medians/MAD; calibrate R Q99
    fit group-vector normalizer, mean/covariance/SVD; validate rank
    calibrate group B Q99 if valid; otherwise preserve unknown reason
  load independently verified sensor-bound table; unknown where absent
  persist profiles, counts, numerical diagnostics and provenance

INFERENCE CONTRACT (not implemented in this stage):
  for each event-time tick after input barrier/watermark:
    compute local B1 for available host records
    for each group:
      validate complete fixed inventory; obtain raw R and B or unknown
      evaluate applicable device bounds; derive three-valued Y
      update causal occurrence history for each method (reset on unknown)
      compute temporal vote2; apply explicitly selected Y policy
      annotate S, E and coverage; update/open/close single group event
    publish raw/preliminary signals and event updates with stable IDs
  close remaining events as censored; record late data separately
```

## 11. Проверяемость и условия перехода к реализации

Ручные контрактные примеры: один хост с десятью экстремумами не даёт R;
два хоста одного канала/знака выше tau_R дают R; ровно tau не даёт сигнал;
rank-deficient B неизвестен; один отсутствующий хост делает R/B неизвестными;
два verified device breaches одного хоста дают только одного Y-witness;
R=1,B=1,Y=? даёт degraded либо preliminary согласно выбранной политике;
общий S всех групп даёт E=0 без отмены события; неизвестность прерывает TTL;
долгий candidate не создаёт повторных ID; δ не использует будущий tick.

Перед реализацией нужны решения о Y-policy, векторе/ранге B, epsilon и
достаточности D1, R min-host rule, δ и event segmentation. После согласования
эти примеры должны стать meaningful unit/contract tests будущего группового
компонента. Протокол оценки — [отдельный документ](group-detection-evaluation-protocol.md).
