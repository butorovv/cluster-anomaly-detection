# Протокол этапа I до нового расчёта

14.10.2026; D1=[00:00,08:00), D2=[08:00,16:00), 18.01.2022 assumed UTC.
Только хешированные реальные D1.bin/D2.bin №4.2. D3 не открывается.
Seed 4301, PCG64; 1999 bootstrap повторов. Параметры ниже фиксированы до запуска.

1. События без изменений воспроизводят select_events №4.2: 60-секундные
приращения, D1 Q99.5 абсолютных приращений, объединение кандидатов с промежутком
≤180 с; t — максимум нормированной амплитуды, а не обязательно начало изменения.
Основная категоризация — доминирующая подсистема и её знак. Дополнительно считаются
события, где 60-секундный интервал одновременно содержит оба знака разных подсистем.
2. Предыдущее состояние: медиана [t−120,t−60], новое: медиана [t,t+30].
Это описательная агрегация, не новая модель. Полные распределения и квантили
1/25/50/75/95/99%, мощности, CPU/GPU температуры, амплитуды, относительного
приращения (делитель max(|pre|,1 W)), A0/B2, B1 margin, робастные координаты.
У PSU нет температуры в F18: не выдумывать соответствующий канал.
3. D1-представленность: host/global ECDF, доля координат вне D1 min/max,
расстояние до ближайшего D1 состояния своего хоста в глобальных F18 scale.
Фиксированная reference-подвыборка — каждое шестое состояние D1 (60 с).
Расстояния до/после описательные, не доказательство неисправности и не плотность.
4. Окна [t,t+30/60/120], [-30,+180] включают обе границы с шагом 10 с.
Any-signal — прежняя метрика. New-onset — false→true в post-части, причём
последние 60 с до t не содержат сигналов (t=0 считается через t−1).
Отдельно: сигнал в pre120, сигнал в t−1, любое post-начало, pre-only,
latency, полная длина нового run, score delta без threshold crossing.
Перекрытия окон разных событий одного хоста считаются и указываются.
5. Длительность нового физического режима: после t мощность остаётся на стороне
midpoint между pre и post в направлении перехода; до первого возврата или конца
D2, последний случай right-censored. Если post не меняется в направлении события,
длительность не определена. Это описательное правило, не критерий отказа.
6. Контроль: тот же host, тот же час D2, тот же D1-дециль предшествующей мощности
доминирующей подсистемы; без сильного перехода во всём [-120,+180] (coverage
№4.2); все наблюдения доступны. Минимизировать |pre_power_event−pre_power_control|,
затем время; выбор без IF scores. Один центр на host не используется повторно.
Если подходящего центра нет — unmatched, без ослабления условий. Одно окно
может перекрываться с другим: зависимость учтена кластерными проверками.
7. Разность paired new-onset(event)−new-onset(control), primary [0,+120].
Percentile CI отдельно bootstrap целых хостов и общих часовых блоков событий
(все методы/пары одного блока вместе). 8 временных блоков — мало: интервалы
описательные, не независимая итоговая оценка; пары могут иметь разные часы
только если изменится протокол (здесь это запрещено). Sensitivity — 30-минутные
блоки. Не делать IID CI строк. Два bootstrap не являются полным двухсторонним
cluster-robust CI; не интерпретировать их как окончательный p-value.
8. Простой baseline: для каждого GPU/CPU/PSU 60-секундные |ΔP|>D1 Q99.5,
тот же исходный физический критерий. Его совпадение с отобранными переходами
частично тавтологично; нужна частота в контролях и длительность, а не заявление
точности. Новые детекторы H2 в этапе I не реализуются.
9. Реальные примеры: для каждой категории крупнейшая нормированная амплитуда,
первое событие с B1/B2 несогласием, первое пропущенное обоими; без ручного
отбора удачных картинок. Графики ECDF, post onset по окнам, pre/post score,
реальные траектории. Раздельные таблицы по группам и хостам.

H0 исследования: асимметрия может быть свойством редкости нового режима и отбора
представителя перехода. Подтверждение причин ограничивается наблюдаемыми связями;
job completion и физическая неисправность без внешних журналов остаются гипотезами.
