База main: 1dfb7c1f8b011b64a8fdebe4de4cdaafc3438940. №4.1: read-only
снимок 79a1441 в results/diagnostics-source; его изменения не объединяются.

1. Только неизменные реальные F18 Summit. D1=[00:00,08:00), D2=[08:00,16:00)
   18.01.2022 UTC по допущению манифеста. D3 запрещено. Основные профили A–D
   не изменяются. Сверка baseline: 12847, 87.33% четырёх a02, F1_ref=0.229418753.
2. A0 historical=0.6850838848387528 отдельно. Основное сравнение A0/B1/B2:
   Q99 исключительно D1, обратная эмпирическая CDF x_(ceil(.99*n)), без
   интерполяции, целые блоки ties, строго >. Медиана — среднее двух центральных
   значений при чётном n. B1 порог на хост; B2 центр на хост и общий scale D1.
   Адаптер к существующему ядру: x−host_median+global_median; ядро выполняет
   единственную нормализацию. Один лес на всех D1, 100/256/8/42.
3. Дополнительные парные A0/B2 seed43,44, B1 от соответствующего A0. Seed не
   выбирается по результатам. Top-K D2 0.5%,1%,2%: K=floor(fraction*n), сортировка
   по убыванию score; B1 ranking=score−host_threshold. Ties timestamp/hostname.
   Это диагностика бюджета, не рабочие пороги и не независимое качество.
4. Физический отбор без моделей: суммарные GPU, CPU, PSU мощности; ΔP=P(t)−P(t−60s).
   Порог каждого |ΔP|=D1-Q99.5. Кандидат превышает хотя бы один порог строго.
   На каждом хосте соседние кандидаты объединяются при разрыве ≤180s;
   представитель — максимум max_j(|ΔP_j|/threshold_j), ties самое раннее время.
   Знак определяется компонентом с максимальным нормированным приращением.
   Температурно согласованная категория: GPU-превышение и одноимённый знак
   ΔP_GPU и ΔT_GPU=T(t+120s)−T(t), |ΔT|>D1-Q99.5(|ΔT|). T — средняя GPU °C.
   Полные до/после окна обязательны; D1/D2 не склеиваются.
5. Реакция: окно [t−30s,t+180s], pre-score среднее [t−120s,t−60s]; прирост
   max score в окне минус pre, первый сигнал относительно t (может быть <0),
   длительность серии, пересекающей окно. Совместные физические события:
   в одной группе объединение представителей с разрывом ≤180s, ≥2 разных
   хостов. События/хосты не считаются IID; агрегаты описательные, без IID p-value.
   Покрытие переходами: объединение [t−60s,t+180s] на соответствующем хосте.
   Устойчивые измеренные режимы: вне покрытия, все |ΔP|≤D1-Q50 и |ΔT|≤D1-Q50.
   Остальное — промежуточное/неопределённое, не объявляется устойчивым.
6. S=K/N, E=S−S_out с фактической доступностью; N=0 или N_out=0 → undefined.
   D1-Q99 для S/E только диагностический уровень, не GroupEvent. Серии >уровня
   и K≥2: максимальная и суммарная длительность, число серий. Известный интервал
   12:24:40–12:29:50 включительно — иллюстрация, не независимый тест.
7. PCG64 seed4202,1999 равномерных перестановок 288 хостов,16×18; одни и те же
   разбиения для всех моделей. Сохраняются бинарные ряды и K_cluster(t).
   Основное семейство 9 односторонних гипотез: для A0-Q99/B1/B2 (a) сумма
   внутригрупповых pair-bins, (b) pair-bins пяти заранее известных a12–a16,
   (c) сумма квадратов E по всем группам/времени. Holm9, alpha=.05,
   p=(1+#control≥observed)/(2000), effect observed−mean и observed/mean.
   Дополнительное семейство144:3 модели×16 групп×(max S,pair-bins,max E),
   Holm144; при разрешении p недостаточном для значимости это явно сообщается.
   Исторический вариант — дополнительная описательная колонка.
8. Вклад a02/четырёх хостов: pair-bins с участием этих узлов, дополнительный
   пересчёт с маской этих четырёх только в диагностике; модели не меняются.
   Межгрупповые pair-bins=все cluster pairs−внутригрупповые. Контроль уже условен
   на точную общекластерную траекторию; дополнительно таблица по точному K_cluster.
9. Хостовые score/частоты D1,D2; >50/90/99%, концентрация четырёх a02, группы,
   серии, сохранённые/потерянные historical сигналы, физические категории,
   реакции, seed, S/E. Mahalanobis — только вспомогательное согласование.
10. SHA256 входов до/после; независимые медианы NumPy, квантили сортировкой,
    обход деревьев Python seed123 (1024 состояний каждого окна/модели), baseline
    №4.1 и его прежний контроль. Все большие данные в results/ (ignored).
    Графики и компактные таблицы в docs. Go test/build/vet и Python tests.

D1 используется и для fit и для калибровки: его частота не независимая оценка
ложных тревог. Ни физические переходы, ни Mahalanobis не являются разметкой
отказов. Снижение частоты не доказывает уменьшение false positives. Итоговый
победитель выбирается только при согласованных независимых основаниях; иначе
отказ от выбора. РПЗ/КР и промышленная модель остаются неизменными.
