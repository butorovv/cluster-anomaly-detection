# Компонентный физический профиль Summit

Реализованы формулы (15)–(39), §§2.5–2.8 компонентной РПЗ
`НИР7_Буторов_РПЗ_07_10_2026_компонентная_модель.docx`:
SHA-256 `8f982d8852e8d79ec3b7a40d8a519eaf6da0a73b98f6ee7bbf16bb2e511be510`.
CPU-регрессия на D2 улучшает MAE относительно сохранения предыдущей температуры
на **0,1533%**; GPU-регрессия ухудшает её на **12,9963%**. Отрицательный `b_G`
сохранён как результат неограниченного МНК. Математическая устойчивость обеих
моделей подтверждена; физическое условие `b_G > 0` не выполняется.

## Данные и область расчёта

Используется существующий `data/prepared/summit-D1-pilot/D1.parquet`, полный день
18.01.2022, SHA-256
`cf3fa634448b7147209bebf3b1c20a1a031be5c047678083adda10581ff562e7`.
288 узлов, группы a01–a16, F18-v1, шаг 10 секунд. D1 — `[00:00,08:00)` UTC,
D2 — `[08:00,16:00)` UTC. D3 не участвует в обучении, оценке или выборе параметров.
UTC — сохранённое допущение manifest; часовой пояс исходного источника не подтверждён.
Статистический профиль этапа A не переобучался. PostgreSQL и исходные Parquet
не изменялись; импорт и создание новых телеметрических Parquet не выполнялись.

Чтение выполняется через прежние `Source.Scan`, `ParquetReader`, `WindowReader`.
WindowReader теперь завершает чтение на исключённой правой границе, проверяя
порядок и дубликаты всех потреблённых строк, включая пропущенный префикс.
Переходы сопоставляются по hostname и одному компоненту; хранится последнее F18
не более чем 288 узлов. Требуется разница времени ровно 10 секунд. История
сбрасывается между D1/D2: температурных остатков на первом timestamp нет.

Частичная запись сохраняется: пригодность проверяется отдельно для каждой пары
и суммы. Требуются конечные координаты, неотрицательная мощность и температура
выше абсолютного нуля. Для перехода проверяется пара компонента на обоих концах;
в регрессор входит **мощность на k**, целевая температура — **на k+1**.
Отсутствующее состояние или координата не заменяется нулём и не соединяется через
пропуск. Температуры разных компонентов не усредняются.

## Коэффициенты и корреляции D1

МНК использует потоковые ортогональные вращения Гивенса для QR-сжатия `[X|y]`.
Gonum 0.17.0 SVD малой R решает МНК и проверяет ранг/обусловленность.
Нормальные уравнения `XᵀX` не формируются. Инженерный относительный SVD cutoff
равен `1e-12`; недостаточное число наблюдений, неполный ранг, нечисловые значения
и обусловленность не ниже `1/cutoff` отклоняются. Условия физических знаков
в оценивание не включаются. Корреляции вычисляются центрированным потоковым
алгоритмом; нулевая дисперсия даёт JSON `null`, а не ноль.

## Проверка на D2

| Класс | Число одинаковых переходов | MAE регрессии, °C | MAE T(k+1)=T(k), °C | Изменение MAE |
|---|---:|---:|---:|---:|
| CPU | 1 658 304 | 0.11906485522312701 | 0.11924768082403758 | -0.153315854570246% |
| GPU | 4 974 912 | 0.29601235757354444 | 0.26196648817930485 | +12.9962689620577% |

На тех же переходах дополнительно рассчитан RMSE:

| Класс | RMSE регрессии, °C | RMSE T(k+1)=T(k), °C | Изменение RMSE |
|---|---:|---:|---:|
| CPU | 0.15828954119443403 | 0.15859446855161033 | -0.19226859546936925% |
| GPU | 0.7008267302611421 | 0.7088871612617917 | -1.1370541661810396% |

RMSE вычислен как `sqrt(Σ e² / n)` по всем отдельным компонентным остаткам
класса, а не как среднее компонентных RMSE. Для каждой регрессии и persistence
использована одна и та же выборка: CPU — 1 658 304, GPU — 4 974 912 переходов
D2. Чтение через существующие Source.Scan/WindowReader и Transitions подтверждено
независимым потоковым NumPy/PyArrow расчётом по ключам `(hostname,timestamp)`
с шагом ровно 10 с. Максимальная разница четырёх RMSE — **3.08e-14 °C**;
покомпонентных RMSE регрессии против сохранённого профиля — **9.44e-15 °C**.
MAE также совпали с сохранёнными результатами с допуском 1e-12 °C.

Положительное изменение означает ухудшение. Небольшой выигрыш CPU не является
доказательством существенного улучшения; проверка статистической значимости не
выполнялась. Для GPU на этом D2 наивный прогноз полезнее по MAE, а регрессия —
по RMSE. Эти результаты совместимы: RMSE придаёт больший вес крупным ошибкам;
МНК минимизирует квадраты ошибок D1, а не MAE. Универсальное преимущество
GPU-регрессии не установлено. Формулы РПЗ, коэффициенты и алгоритмы не менялись.

Сохраняются восемь отдельных распределений температурных остатков и один PSU:
число, среднее со знаком, MAE, RMSE, минимум, максимум и генеральная дисперсия.
PSU на D2: MAE **127.72703358937915 Вт**, RMSE **153.34670023880713 Вт**.
Температурные остатки и остаток PSU — диагностические показатели, бинарных меток нет.

Для обеих моделей `|a| < 1` и `0 < a < 1`. У CPU `b > 0`; у GPU `b < 0`.
Равновесие вычисляется строго как `(b*P+c)/(1-a)`; при `a=1` оно неопределено.
При **наблюдаемой средней компонентной мощности D1**:
CPU — P=54.11681770978359 Вт, T*=29.811332139289213 °C;
GPU — P=132.55897562902388 Вт, T*=39.288384542969546 °C.
Эти средние используются только как явно указанные опорные мощности для отчёта.

J рассчитан для **a01n01 / CPU0**, полного доступного непрерывного ряда прогнозов
D2, с включёнными границами **08:00:10–15:59:50 UTC**. Начальная температура
08:00:00 используется только как вход первого прогноза. Получены 2 879 остатков,
MAE ряда **0.11027553863985559 °C**, J **3174.8327574414425 °C·с**.
Проверяется `J = 10*Σ|e| = n*10*MAE` на том же ряду. Интервал задаётся явно;
через пропуски J не вычисляется, отсутствующие остатки не заменяются нулями.

## Проверка отрицательного b_G

Сопоставление сохранённого manifest, domain и F18:

| GPU | Raw power | Raw temperature | Индексы F18 (с нуля) |
|---|---|---|---|
| GPU0 | p0_gpu0_power | gpu0_core_temp | 4, 12 |
| GPU1 | p0_gpu1_power | gpu1_core_temp | 5, 13 |
| GPU2 | p0_gpu2_power | gpu2_core_temp | 6, 14 |
| GPU3 | p1_gpu0_power | gpu3_core_temp | 7, 15 |
| GPU4 | p1_gpu1_power | gpu4_core_temp | 8, 16 |
| GPU5 | p1_gpu2_power | gpu5_core_temp | 9, 17 |

На 1 728 состояниях всех 288 узлов в шести фиксированных timestamp D1
(00:00:00, 00:00:10, 04:00:00, 04:00:10, 07:59:40, 07:59:50) все F18 точно
совпали с raw `20220118.parquet` по `(hostname,timestamp)`: 10 368 GPU-пар,
максимальная разница 0. Повторной подготовки или импорта не было.

Независимый NumPy 2.2.5 / PyArrow 24.0.0 расчёт читает ограниченные блоки, ищет
предыдущий отсчёт по составному ключу `(timestamp-10s,hostname)`, отдельно выбирает
каждый компонент и использует блочный Householder QR + `numpy.linalg.lstsq`.
Все числа переходов совпали. Максимальные абсолютные разницы коэффициентов:
CPU **1.86e-12**, GPU **7.58e-11**, PSU **1.33e-9**.
Корреляций — **3.16e-14**, MAE регрессии — **8.89e-16**, наивного прогноза —
**3.40e-14**, J — **1.37e-12**. Время независимой проверки с baseline — 3.631 с.
Исходные результаты и скрипты проверки сохранены локально в `results/` вне Git.

Положительный r_GPU не требует положительного частного коэффициента мощности
в регрессии с T(k). Ошибки принятого сопоставления, сдвига k/k+1 или QR/SVD
не обнаружены.

Дополнительная диагностика D1 установила статистический эффект объединения
неоднородных рядов. Все шесть регрессий GPU0–GPU5 по совокупности узлов имеют
отрицательный b; он также отрицателен во всех 16 группах и в 285 из 288 узлов
при объединении шести GPU внутри узла. Однако у отдельных рядов hostname × GPU
**1714 из 1716 идентифицируемых регрессий имеют b > 0**, две — b < 0.
Ещё **12 рядов вырождены** из-за постоянной температуры: их коэффициенты
не определяются однозначно, и знаки не интерпретируются. При вычитании средних
каждого ряда диагностический общий коэффициент становится
**b_within = +0.0024952814904444995 °C/Вт**. На различия средних рядов приходится
**93.05% общей дисперсии температуры** на той же выборке переходов D1.
Выборочные индивидуальные регрессии проверены прямым NumPy lstsq; диагностические
оценки не внедрены в модель и не выбирались по D2.

Установленными фактами являются неоднородность уровней температуры, смена знака
при объединении рядов и различие результатов по MAE/RMSE. Они ограничивают
физическую интерпретацию общего b_G и не означают охлаждение от роста мощности.
Причины неоднородности — охлаждение, среда, нагрузки, особенности датчиков или
синхронизации исходных измерений — остаются неподтверждёнными физическими
объяснениями. Положительные индивидуальные коэффициенты также не доказывают
причинность. β₀ не трактуется как измеренная постоянная мощность остальных
устройств, β₁ — как КПД PSU.

## Сохранение и воспроизведение

Первый полный профиль с D1/D2:
`results/physical-20220118-v1.json` (13 771 байт, вне Git).
Дополнительная оценка того же профиля на D2 с наивным прогнозом:
`results/physical-20220118-v2-d2.json`. Все восемь коэффициентов сохранены точно.
Загрузка проверяет версию, D1, шаг, коэффициенты, численные соглашения, rank/condition,
числа наблюдений и привязку к SHA-256, топологии и timezone metadata источника.
Неправдоподобный знак b_G не считается повреждением профиля.

Из корня репозитория (указать новые имена output):

```powershell
go run ./cmd/physical --output results/physical-new.json --j-host a01n01 --j-component CPU0 --j-start 2022-01-18T08:00:10Z --j-end 2022-01-18T15:59:50Z
go run ./cmd/physical --profile results/physical-new.json --output results/physical-new-reloaded.json --j-host a01n01 --j-component CPU0 --j-start 2022-01-18T08:00:10Z --j-end 2022-01-18T15:59:50Z
go test ./...
go build ./...
go vet ./...
$env:NIR_REAL_PARQUET=(Resolve-Path data/prepared/summit-D1-pilot/D1.parquet).Path
$env:NIR_REAL_PHYSICAL_PROFILE=(Resolve-Path results/physical-new.json).Path
go test -v ./internal/experiment -run TestRealPhysicalProfileReloadD2 -count=1
```

Без J-флагов интервал не выбирается автоматически. Все четыре J-флага должны
задаваться вместе. `--profile` выполняет только применение к D2, без МНК.
SaveNew отказывается перезаписывать результаты.

Фактически прошли `go test ./...`, `go build ./...`, `go vet ./...` и opt-in
`TestRealPhysicalProfileReloadD2`: все девять сводок остатков, MAE, baseline и J
повторно вычислены на полном D2 и совпали точно с сохранённой оценкой.
Быстрые тесты проверяют формулы, F18, точные временные пары, пропуски, границы,
неограниченный МНК с известными коэффициентами, вырожденность/обусловленность,
нулевую дисперсию, равновесие, критерии устойчивости, J и загрузку профиля.
DB-интеграция без TEST_DATABASE_URL и реальные Stage A opt-in тесты без их
переменных пропущены; это не заявляется как выполненная реальная проверка.
При финализации пропущены `TestPostgresHistoryWithCanonicalSchema`,
`TestSmallRealD1Snapshots`, `TestRealStatisticalProfileReload` и
`TestRealPreparedDayWindows`: соответствующие opt-in переменные не заданы.
Последний тест включает D3 и в финализации этапа B не выполнялся.
`TestRealPhysicalProfileReloadD2` отдельно запущен с явно заданными существующими
