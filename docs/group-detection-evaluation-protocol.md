## Замораживаемые параметры

Зафиксировать spec version/commit и SHA входов; group inventory; 10D основной
вектор (либо отдельно утверждённую 5D альтернативу); R two-host rule и D1 Q99;
MAD floor; B normalization/ddof/SVD/rank policy; verified sensor-bound table;
Y-policy; δ; gap merging=0; unknown/censoring policy; локальный B1; outside universe.
До анализа D2 публиковать D1 counts, zero-MAD/floored scales, eigen/singular
spectrum, rank/condition и число непригодных групп. Непригодность не лечить
скрытой сменой вектора или ridge. Полный Y и degraded R+B — разные режимы отчёта.

Sensitivity grid: δ=0,10,30,60 s, все четыре результата. Основное предложение
δ=0 не объявляется оптимальным. Не перебирать дополнительные пороги до
положительной картинки. Изменение гипотезы фиксировать явно и проверять на
новых данных, когда они появятся.

Масштабирование: 4/8/16 групп, вложенные списки a01–a04, a01–a08, a01–a16
по текущему inventory. Одни и те же профили общих групп и B1, без переобучения
при каждом размере; outside определяется выбранным universe. Поэтому E между
размерами не обязан совпадать. Дополнительно можно сохранить E относительно
всех 16 как отдельную контрольную характеристику, не смешивая знаменатели.

## Измеряемые результаты

| Характеристика | Точное правило / ограничение |
|---|---|
| Coverage | По группам/ticks: полные F18, IF available counts, R/Y/B unknown и причины |
| Raw signals | Число положительных R,Y,B, знаменатели известных, rates на доступные ticks |
| Пересечения | Все 8 комбинаций известных бинарных голосов; отдельно unknown combinations; R/B contingency, Jaccard/phi при определённых знаменателях |
| Candidates | Число положительных temporal candidate ticks отдельно для full/degraded/preliminary; δ и eligible denominator |
| Events | Число сегментированных событий, не число candidate ticks; censoring, raw duration, TTL duration |
| IF support | a/n по реально доступным; distribution/min/mean/max и coverage; без обязательного gate |
| Spatial comparison | S_outside, E, синхронная карта групп, сравнение с общим изменением режима |
| Delay | first evidence→logical confirmation; watermark wait, compute latency отдельно; true onset только при независимой метке |
| Sensitivity | Все четыре δ: count, overlaps, merged/extended spans, delay; не выбирать по D3 |
| Incremental value | События R-only, B-only, Y-only и пересечений, признаки/хосты-свидетели; сравнивать при одинаковых frozen settings |
| Performance | Wall time, states/s, ticks/s, sampled heap и process peak RSS раздельно; cold/warm cache, CPU/OS/Go, repeats |

Отчёт должен включать отрицательные и unknown результаты, длительные события,
а не только наиболее эффектные эпизоды. Начальные/конечные censored events
не смешивать с полностью наблюдавшимися durations. Для end-to-end stream latency
нужна будущая online-система; нынешний offline-runtime этого не доказывает.

Если потребуется оценка неопределённости, использовать блоки времени с длиной,
обоснованной автокорреляцией D1, а не независимые host-ticks. Пространственно
связанные группы не считать независимыми повторами. Непрерывный 8h фрагмент
не даёт гарантии общесуточной/междневной устойчивости. 16 групп и grid δ создают
множественность сравнений; не выбирать один лучший результат без оговорки.

Без реальных labels не вычислять «качество неисправностей» Precision/Recall/F1.
Исторический F1 против узлового D² измеряет согласие с псевдоразметкой.
При появлении независимых incident labels заранее определить event matching,
временной допуск, one-to-one сопоставление, censoring и observable negatives.
Синтетические инъекции допустимы только отдельной будущей задачей: они проверяют
чувствительность заданной модели вмешательства, а не точность реальных отказов.

## Воспроизведение и ресурсы

Сохранять run manifest: code commit, все SHA, immutable config, seeds (если
используется sampling), timestamps, dependency versions, machine, command,
exit status; raw criterion scores/statuses, event evidence и summary. Каждый
запуск пишет новый каталог, не меняет исходные данные/исторические результаты.
При сравнении версий давать полный diff конфигураций и одинаковые входные SHA.

Пусть H=18G, T=ticks, d=10, K=5, F=100 trees, depth=8.
Inference B1 O(T*H*F*depth); агрегаты/R O(T*H*K) при линейном поиске second max;
B O(T*G*d²). Exact D1 medians/quantiles требуют scalar arrays O(T1*H*K + T1*G*d)
при прямой реализации, covariance O(G*d²), SVD O(G*d³).
Streaming inference помимо decoder/forest — O(H*K+G*d²+G*δ/Δ) для bounded history
и агрегированных событий. Хранение всех event raw samples нарушило бы эту оценку:
их следует писать потоково, в памяти держать summaries. Это оценки будущего
контракта; фактические memory/throughput групповой реализации ещё не измерены.

Порядок: утвердить spec → D1 diagnostics/profile validity → D2 grid и методологический
разбор → заморозить новую версию → ретроспективный D3 с оговоркой либо новый
неиспользованный день → независимая интерпретация по logs. До утверждения spec
не начинать групповой detector/state machine или распределённый pipeline.
