## Статус исследования и неизменяемая основа

D2 уже изучался в PR №10. Это дополнительные разведочные исследования,
заранее описанные относительно новых прогонов, а не независимое проспективное
подтверждение. Новые данные не скачиваются, D3 не читается и не используется
для выбора параметров. UTC остаётся прежним неподтверждённым допущением источника.

Рабочая модель `summit-group-research-v1`: пять физических каналов, 10D
mean/population spread, temporal Median/MAD ×1.4826 с floor 1e-4 W/°C,
second-largest двух различных хостов одного канала/знака, строгий D1 Q99;
B: robust normalization, Welford ddof=1, SVD rcond=1e-12, rank=10 либо unknown.
Основной δ=0, Y unknown, предварительное R+B. IF и индивидуальные B1-пороги
сохраняются. Исходные 899 R+, 3260 B+, 682 R&B, 285 событий не заменяются.

SHA исходных данных, моделей, конфигураций, production-кода и исторических
результатов сохранены в [protected-sha256.json](group-validation-v1/protected-sha256.json).
Разрешены точечные правки актуальных README/architecture и тестовой конфигурации;
исторические отчёты, в том числе PR №10, остаются неизменными.

## Гипотезы и разделение выводов

H1: документированная hostname-группировка может концентрировать согласованные
изменения иначе, чем случайное разбиение. Направление различия не предполагается.
H2: доля IF-поддержанных ticks и пересечение хостов информативнее слабого признака
«есть хотя бы один IF+». H3: минимальное двуххостовое правило R и 10D B могут
по-разному реагировать на фиксированные коллективные изменения. H4: пропуски
обязаны давать unknown, разрыв события и отсутствие TTL-переноса через разрыв.

Синхронность и hostname encoding не доказывают общий PDU/cooling/IB fault domain.
Число событий не является числом отказов. R и B используют общие F18/D1;
их голоса не считаются независимыми физическими подтверждениями.

## Реальные события, общие эпизоды и IF-контроль

Источник — сохранённые D2 F18/score exports и таблицы PR №10. Сначала сверяются
baseline и численная эквивалентность расчёта (`rtol=atol=1e-8`, binary exact).
Все 285 событий анализируются, без отбора по привлекательности графиков.
Длительности: 10 s; 20–30 s; 40–120 s; >120 s. На событие сохраняются
группа/время/длительность, R witnesses и физические amplitudes, B/threshold,
IF tick fraction, distinct hosts, mean/max hosts/tick, пересечение IF и R-хостов.
Ближайшее IF+ ищется в ±60 s от detected time; задержка знаковая,
ties выбирают более раннее время, отсутствие — null.

Контроль каждого события: та же группа, та же длина, полные данные, ни одного
GroupCandidate внутри и в guard ±60 s. Предпочтение того же часа начала;
далее минимальное расстояние start-time, tie — более ранний start. Повторное
использование контроля допускается и показывается. IF не участвует в отборе.
Если контроля нет, сохраняется явная причина, событие не исключается молча.

Общий эпизод заранее задан: [12:24:00,12:31:00) для всех 16 групп, отдельно a12–a16.
Другие эпизоды — **все** максимальные непрерывные интервалы, где одновременно
положительны не менее пяти групп при δ=0. Порог 5 фиксирует описание охвата,
не становится фильтром детектора. Физический reference — предшествующие 300 s;
в начале D2 сохраняется фактическая длина доступного reference. Сравниваются
мощности/температуры, R/B onset, IF и последовательность между группами.

## Перестановочный контроль

20 seeds 2026101801…2026101820; генератор NumPy 2.3.5 PCG64.permutation.
Все 20 составов 16×18 записаны в JSON **до анализа**. Каждый из 288 хостов
входит ровно один раз; порядок внутри контрольной группы сохраняется из
перестановки. F18 и timestamps не меняются, IF остаётся привязан к реальному hostname.

Каждый контроль получает **собственные** D1 R/B normalization, covariance/SVD
и Q99. Профиль настоящей группы не переносится. Непригодные B сохраняют unknown
с rank/причиной; seed не заменяется. Реализация — отдельный исследовательский
инструмент, без ослабления production hostname-проверок.

Сравниваются R+/B+/R&B, события/длительности, доли R-witness hosts,
HHI/энтропия событий по группам, количество одновременно активных групп,
устойчивость серий, физические каналы/направления и IF-поддержка. Публикуются
все 20 результатов, min/median/max и положение исходной группировки.
Показатели описательные; обычный независимый tick-level significance test
не применяется. Контроли сохраняют общую временную структуру и потому не
являются независимыми календарными днями. Изменяется также состав нагрузок,
масштабов и совместное расположение zero-MAD каналов: эффект нельзя приписать
только физической топологии. Большее/меньшее число тревог не означает лучшее качество.

## Контролируемые воздействия

Каждый сценарий — отдельная копия неизменного D2 в памяти, один прогон, без refit.
Seeds записаны в конфигурации, но случайный шум не применяется. Окна полуоткрытые.

| Сценарий | Интервал UTC | Хосты | Изменение F18 |
|---|---|---|---|
| A | 10:00–10:02 | a04n01 | +5 °C каждому из шести GPU temperature |
| B | 10:00–10:02 | a04n01–02 | то же |
| C | 10:00–10:02 | a04n01–06 | то же |
| D | 10:00–10:02 | все a04 | то же |
| E | 11:00–11:02 | все a04–a06 | +20 W каждому GPU power; +75 W каждому PSU AC power |
| F | 12:27:00–12:27:10; 12:28:00–12:28:30 | a02n01; затем все a02 | удалить соответствующие host-ticks |

Амплитуды — круглые фиксированные scale probes (+5 °C mean, +120 W GPU total,
+150 W PSU AC total), не sensor limits и не достоверные модели неисправностей.
Температура/мощность изменяются без динамической тепловой модели: это
**mathematical perturbations**. A–D имеют одинаковое время/амплитуду, отличаются
только числом затронутых хостов. F намеренно пересекает известный baseline
эпизод, чтобы проверить разрывы. Ничего не записывается в исходный Parquet.

R/B и локальные IF для изменённых состояний проверяются существующим Go-ядром;
исходные score/решения сохраняются рядом. Измеряются R/D² increments, host
witnesses, IF, дополнительное R&B относительно baseline, onset delay от начала
воздействия, события за пределами затронутых групп и unknown. Уже положительный
baseline не засчитывается новым обнаружением. Один изменённый хост на реальном
фоне может составить пару с уже отклонённым вторым: это не нарушение min-two rule.

## Zero-MAD, пригодность и публикация

Готовая диагностика PR №10 (899→726 R+, 682→550 R&B, 285→277 событий)
используется повторно без нового refit/поиска floor. a02 разбирается отдельно.
Исключение координат не называется доказанным улучшением.

Успешность исследования: точный baseline, валидные составы всех контролей,
отдельное D1 обучение, задокументированная численная пригодность каждого B,
соответствие Go/Python и unknown-семантике, неизменные защищённые SHA,
публикация отрицательных результатов без перенастройки. Любое отступление от
протокола обозначается отдельно и не выдаётся за исходный план.

В Git: компактные JSON/таблицы, код, конфигурации, SHA и основные PNG/SVG.
Полные profiles/scores/NDJSON/CSV новых прогонов — отдельный ignored `results/`.
Run manifest: protocol commit/SHA, code commit/dirty state, версии зависимостей,
команды, seeds, input/output hashes и измеренное время. Финальные документы:
научная модель НИР, записка для научного руководителя и проект distributed-контракта КР.
Kafka/Worker/Master/HTTP/GUI не реализуются. Согласование руководителя не заявляется.
