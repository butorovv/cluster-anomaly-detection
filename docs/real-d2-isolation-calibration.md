## Реализация

`internal/analysis/calibration.go` сортирует копию пар score/псевдометка и
проходит блоками одинаковых score. Изначально все состояния предсказаны
положительными; целый блок удаляется до проверки его score как порога.
Это реализует строгое `score > theta_IF`, без дробления равных значений.
Кандидаты — только наблюдаемые значения; порог ниже минимума не добавляется.
Сложность `O(n log n)` для сортировки и `O(n)` для прохода; память `O(n)`.
Сохраняются скалярные пары, не весь набор F18. Копия не меняет вход вызывающего.

```text
Precision_ref = TP / (TP + FP)
Recall_ref = TP / (TP + FN)
F1_ref = 2 TP / (2 TP + FP + FN)
```

Сравнение F1 использует 128-битные целочисленные произведения числителя и
знаменателя, без epsilon и округления float64 при выборе максимума. Равные
максимумы выбираются по большему score. Счётчики проверяются на отрицательные
значения/переполнение. Неопределённые Precision, Recall, F1 — `null`, не ноль.
Кандидат с неопределённым F1 пропускается и учитывается отдельно. Если ни у
одного кандидата нет определённого F1, сохраняются `status=undefined_f1` и
`theta_if=null`; применение такого результата возвращает ошибку.

При отсутствии положительных псевдометок и разных score определённые F1
равны нулю: выбирается наибольший порог среди них, а максимальный score
(нет предсказанных положительных, знаменатель F1=0) пропускается. При всех
равных score и наличии положительных единственный кандидат даёт F1=0,
Recall=0 и неопределённый Precision. Эти случаи покрыты тестами.

`internal/experiment/calibration.go` использует существующие `OpenSource`,
`LoadIsolationProfile`, нормализатор Stage A и `Source.Scan`. Окно фиксировано
как D2. `cmd/calibration` не имеет настроек обучения и не вызывает Fit.
Загрузка результата проверяет версию, правило выбора/сравнения, F18, окно,
audit, счётчики и метрики, SHA-256 и версии обоих D1-профилей, источник,
топологию и сохранённый порог Mahalanobis. Копии моделей по другому пути
допустимы при идентичных байтах. Порог можно применять через
`ThresholdCalibration.Label` без повторной настройки.

## Проверки

`go test ./...`, `go build ./...`, `go vet ./...` завершились с exit code 0.
Unit-тесты проверяют формулы/неопределённость метрик, строгое сравнение,
равные score и максимумы F1, all-equal/no-positive случаи, нечисловой ввод,
отмену context, точное сравнение за пределами точности float64, JSON round trip
и повреждения/несовпадения сохранённой калибровки и исходных моделей.
На 500 случайных маленьких наборах эффективный подбор совпал с независимым
прямым перебором всех кандидатов и точными дробями `math/big.Rat`.

`TestRealIsolationCalibrationReloadD2` повторно вычислил весь D2 с загруженным
порогом: audit, confusion matrix, метрики и IF-срабатывания совпали точно;
калибровка не изменилась. Прогон занял 12,72 с. CLI `--calibration` также
завершился с `reload_matched=true`, без поиска; 27,45 с при параллельной нагрузке.
Отсутствующие переменные opt-in и `TEST_DATABASE_URL` означают SKIP для
остальных реальных/DB-проверок. PostgreSQL в этом эксперименте не используется.

Независимый `tools/dataset/verify_calibration.py` на NumPy 2.3.5 / PyArrow
26.0.0 прочитал D2 batches по 8 192 строки, заново вычислил IF-пути,
гармоническую поправку, Mahalanobis и псевдометки, затем выполнил сортировку,
prefix sums и точное сравнение F1 Python-целыми. Confusion matrix, 9 880
псевдометок, 12 847 IF-срабатываний и все три метрики совпали **точно**.
Порог — 0.6850838848387527, расхождение 1.11e−16; максимум один.
Oracle получил 819 215 различных score против 819 214 в Go: округление
гармонической суммы/exp2 в независимых реализациях меняет слияние близких
float64-значений. Максимум и выбранная классификация совпали; epsilon для
слияния Go score не добавлялся. Проверка заняла 16.7181595 с.

## Воспроизведение и ограничения

```powershell
go run ./cmd/calibration --output results/calibration-fresh.json
go run ./cmd/calibration --calibration results/calibration-fresh.json --output results/calibration-fresh-reloaded.json
$env:NIR_REAL_PARQUET=(Resolve-Path data/prepared/summit-D1-pilot/D1.parquet).Path
$env:NIR_REAL_PROFILE=(Resolve-Path results/statistical-20220118-8h-v1.json).Path
$env:NIR_REAL_ISOLATION_PROFILE=(Resolve-Path results/isolation-20220118-v1.json).Path
$env:NIR_REAL_CALIBRATION=(Resolve-Path results/calibration-fresh.json).Path
go test -v ./internal/experiment -run TestRealIsolationCalibrationReloadD2 -count=1
python tools/dataset/verify_calibration.py --calibration results/calibration-fresh.json --isolation-profile results/isolation-20220118-v1.json --statistical-profile results/statistical-20220118-8h-v1.json --input data/prepared/summit-D1-pilot/D1.parquet
```

Python-команда требует NumPy/PyArrow. На этой машине использованы существующие
bundled Python и `.venv/Lib/site-packages` через PYTHONPATH без установки пакетов.
UTC первичного источника остаётся прежним неподтверждённым допущением manifest.
D3 для расчёта и выбора решений не использован. GroupResult, GroupEvent,
топологическая агрегация и испытания D3 не реализованы.
